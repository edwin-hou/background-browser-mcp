# Troubleshooting

| Symptom | Check |
| --- | --- |
| Bare dashboard URL says to use the private shortcut | Expected. Open the generated `Open browser setup.url`; do not paste its token into chat. |
| Dashboard or local MCP is unreachable | Start this installation with its Start shortcut. Inspect management Status. Confirm the PC is signed in and ports 8933–8936 are not occupied by another installation. |
| A website redirects to sign-in | Renew the session through that website's setup card, save it explicitly, and verify the authenticated page again. A green service status is not a website login. |
| A login window is already open | Finish that same window and save it before opening another. Do not open another process against the same profile. |
| Google says the browser or app may not be secure | Retry through the dashboard's sign-in card. The login helper starts installed Chrome directly and then connects through Chrome debugging, using only this installation's separate profile. Check Chrome updates, JavaScript, and unsupported extensions. Google can still decline sign-in; no universal Google-login compatibility is claimed. |
| MCP appears configured but no browser tools are available | Reload the connection/client and verify tool exposure in the exact chat. Local config does not enable a hosted ChatGPT plugin. |
| A long-running chat reports Transport closed or Session not found | Use the local stdio bridge configuration generated by the current installer. The hosted gateway and bridge reconnect stale backend sessions before dispatch. Direct HTTP clients need to initialize a new session after a backend restart. |
| Browser recovery reports health-inspection-failed | Check its sanitized inspection classification and elapsed time. The current inspector reuses one Windows process snapshot; it retains strict process-identity checks and a bounded timeout. |
| Upgrading an older installation's recovery controller | Finish active browser work, use the installation's intentional Stop, then Start with the updated source. Older Node controllers can terminate their workers when the controller exits; existing children cannot be detached retroactively. |
| An action reports completion unknown | Inspect the current page to establish whether it completed before retrying. The bridge and hosted gateway deliberately do not repeat uncertain writes. |
| Dashboard shows Sign-in required | Open that card's Reconnect account action, complete website sign-in/MFA yourself, and save the session. The pending task waits; authenticated access must be verified before continuing. |
| Dashboard shows Sign-in status not checked | No recent supported authentication evidence was observed. This does not mean the account expired. Website checkpoints alone do not prove authentication. |
| Dashboard says Connection status is unavailable | It cannot currently obtain live status; keep the page open for another check or reopen the private setup shortcut. It does not infer that every website account is signed out. |
| Gateway is reachable but ChatGPT request failed | The request-history banner records the actual failure separately. Pause account work, reconnect, then verify access. A later successful request clears connection failure but an interrupted action still needs outcome verification. |
| No ChatGPT request is recorded | No authenticated forwarded request has reached this installation. Check the plugin connection/exposure in ChatGPT; a local dashboard cannot observe a request blocked before reaching the PC. |
| Navigation returns a local file path | Ask for `browser_snapshot` without a filename to get inline page state. |
| ChatGPT cannot create the plugin in the desktop dialog | Use ChatGPT on the web with the same account; check account/workspace access and the current official setup guide. |
| ChatGPT OAuth fails | Use your own stable domain, OAuth with DCR, public-client auth `none`, and scope `browser:control`. Verify exact callback/issuer values. Leave CIMD/OIDC off for this gateway. |
| Tunnel is running but ChatGPT tools fail | Check gateway health, ngrok account/domain and quotas, then complete real OAuth and a tool call. A process PID does not prove remote access. |
| Windows startup says a file cannot be found although it exists in an app | Check the actual physical path from outside that app. Reinstall into a fresh normal user-profile folder rather than an MSIX-virtualized location. |
| Explicit Stop immediately restarts | Use the project's Stop action rather than killing a browser child. Stop writes durable disabled policy before shutdown. |

Do not “fix” remote access by tunneling ports 8933, 8935, or 8936, disabling gateway authentication, copying cookies, or changing redirect allowlists to wildcards. Preserve your existing profile while diagnosing an issue.

Chrome documents [starting Chrome separately and connecting afterward](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/docs/advanced-usage.md#connecting-to-a-running-chrome-instance) as an alternative when accounts reject a browser launched through WebDriver. The helper uses a loopback debugging port for this dedicated profile and preserves the existing session handoff. It does not change the user agent, JavaScript fingerprint, automation properties, or Google account security settings. Routine browsing still returns to the headless background service after you save or close the login window. The Google account must be tested again after that transition; manual sign-in success alone does not prove background access.

For Drive, Docs, Sheets, and Slides, a connected Google Drive integration is another option that uses Google's APIs instead of website login. API access and website cookies are separate authorizations. Google's [supported-browser troubleshooting](https://support.google.com/accounts/answer/7675428?co=GENIE.Platform%3DDesktop&hl=en) also lists browser updates, JavaScript, and extensions as checks; do not disable account protection to force a sign-in.

If installation fails, report its sanitized error text and which step failed. Do not post the installation directory, private shortcut, browser artifacts, or raw OAuth/ngrok files as a support bundle.

Connection health uses passive local checks and a cached public gateway health check; it does not open account tabs. Account observations are currently conservative for supported Vanderbilt Brightspace and Google Drive/Docs flows. A known sign-in form must be reached through an attributable saved-site request. Other providers and ambiguous flows remain not checked. Private observation files contain only a site ID, status, time, and fixed reason code; they contain no page contents, account names, credentials, or query strings. Reconnection saves a new checkpoint and clears stale attention, but only a subsequent protected-page read can verify access.
